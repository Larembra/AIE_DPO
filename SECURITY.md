# Политика безопасности и работы с данными

Ниже перечислены правила, которые необходимо соблюдать при работе с репозиторием.

---

## 1. Общие принципы

1. Репозиторий не должен содержать:
   - реальные персональные данные третьих лиц;
   - секреты доступа: пароли, токены, приватные ключи и т. п.;
   - конфиденциальную или служебную информацию.

2. Вся информация, размещённая в репозитории, рассматривается как потенциально доступная внешней аудитории.

3. При работе с реальными данными рекомендуется:
   - применять обезличивание или анонимизацию;
   - по возможности заменять реальные данные синтетическими.

---

## 2. Запрещено добавлять в репозиторий

Строго запрещено добавлять:

- **Секреты и учётные данные:**
  - пароли, API-токены и ключи доступа, включая токены Telegram, Discord, VK, GitHub и облачных сервисов;
  - приватные ключи (`id_rsa`, `.pem`, `.key` и другие);
  - файлы `.env` с реальными секретами;
  - cookie, экспортированные сессии и дампы менеджеров паролей.

- **Персональные данные третьих лиц:**
  - реальные ФИО, телефоны, адреса, адреса электронной почты и логины;
  - паспортные данные, номера полисов, СНИЛС и другие подобные сведения;
  - таблицы и выгрузки с идентифицирующей информацией.

- **Конфиденциальную и служебную информацию:**
  - закрытые внутренние документы организаций;
  - выгрузки из реальных внутренних систем без явного разрешения.

При случайном добавлении секрета или персональных данных необходимо:

1. немедленно удалить файл из репозитория;
2. при необходимости переписать историю репозитория;
3. отозвать или заменить скомпрометированные секреты.

---

## 3. Допустимые данные

В репозитории можно использовать:

- общедоступные открытые датасеты с OpenML, Kaggle, UCI и других ресурсов, если это не нарушает условия лицензии;
- синтетические данные, созданные специально для проекта;
- обезличенные данные, по которым невозможно восстановить личность;
- небольшие демонстрационные выборки для запуска проекта — без персональных данных и секретов.

При сомнениях рекомендуется не размещать данные в репозитории, пока не будет подтверждена возможность их публикации.

---

## 4. Конфигурации и файлы `.env`

- Реальные секреты и пароли необходимо хранить локально, вне репозитория.
- Для конфигураций следует использовать:
  - файлы в `project/configs/`, например `config.yaml`;
  - шаблоны окружения, например `.env.example`, без реальных значений.

Рекомендуемый подход:

1. В репозитории хранится `project/configs/.env.example` со списком переменных окружения без секретных значений.
2. Локально, вне репозитория, хранится файл `.env` с реальными значениями. Этот файл должен быть добавлен в `.gitignore`.

---

## 5. Поддержка чистоты репозитория

Файл `.gitignore` помогает:

- не добавлять в Git временные файлы, кеши и виртуальные окружения;
- предотвращать случайное добавление `.env` и некоторых других служебных файлов.

Перед коммитом необходимо:

1. просмотреть список изменённых файлов с помощью `git status` и `git diff`;
2. убедиться, что среди них нет неожиданных файлов данных, секретов и временных артефактов.

---

## 6. Ответственность за содержимое репозитория

Соблюдение этих правил:

- снижает риск утечки данных и компрометации аккаунтов;
- помогает соблюдать требования законодательства о персональных данных и внутренние политики организаций;
- способствует применению корректных практик разработки ИИ-систем.

Если допустимость размещения конкретного файла вызывает сомнения, его не следует добавлять в репозиторий до выяснения условий публикации.
